# Django 项目完整部署方案
> 生产环境推荐组合：**Django + Gunicorn + Nginx + MySQL + Linux（Ubuntu/CentOS/Rocky）**
> 开发不要用 `python manage.py runserver` 当生产服务，它只适合调试。

## 一、前置准备（服务器端）
### 1. 基础环境安装（Ubuntu 22.04 示例）
```bash
# 更新源
sudo apt update && sudo apt upgrade -y

# 安装依赖
sudo apt install python3 python3-pip python3-venv nginx mysql-server -y
```

### 2. 上传项目代码
两种方式任选：
1. git拉取：`git clone xxx.git`
2. 本地打包上传（scp、LocalSend、宝塔等）

> 假设项目目录：`/home/youruser/django_project/`

## 二、创建虚拟环境（隔离依赖，必做）
```bash
# 进入项目根目录
cd /home/youruser/django_project

# 创建虚拟环境
python3 -m venv venv

# 激活虚拟环境
source venv/bin/activate

# 安装项目依赖
pip install -r requirements.txt

# 额外安装生产wsgi服务器
pip install gunicorn
```

> 退出虚拟环境命令：`deactivate`

## 三、Django 项目配置修改（settings.py）
### 1. 关闭调试模式
```python
DEBUG = False
```
### 2. 允许访问域名/IP
```python
# 填写服务器公网IP、域名
ALLOWED_HOSTS = ["127.0.0.1", "你的服务器IP", "www.xxx.com"]
```
### 3. 静态文件配置（关键！Nginx负责托管静态资源：css/js/img/admin）
```python
STATIC_URL = '/static/'
# 静态文件收集目录
STATIC_ROOT = BASE_DIR / 'static'

# 媒体文件（用户上传文件，可选）
MEDIA_URL = '/media/'
MEDIA_ROOT = BASE_DIR / 'media'
```

### 4. 收集静态文件
虚拟环境激活状态下执行：
```bash
python manage.py collectstatic
```
> 会把所有静态文件统一复制到 `STATIC_ROOT` 文件夹。

### 5. 数据库迁移
```bash
python manage.py migrate
# 创建超级管理员
python manage.py createsuperuser
```

## 四、Gunicorn 配置（WSGI应用服务器，跑Django程序）
> Gunicorn 接收 Nginx 转发的动态请求，运行Django；不直接对外暴露公网。

### 测试启动（先验证能不能跑通）
```bash
# myproject.wsgi  → myproject是项目同名文件夹，里面wsgi.py
gunicorn --workers=2 --bind=127.0.0.1:8000 myproject.wsgi:application
```
- `--workers=2`：工作进程，一般设 `CPU核心数 * 2 +1`，小服务器2~4足够
- `--bind=127.0.0.1:8000`：只监听本机端口，外部不能直接访问

访问 `http://服务器IP:8000` 测试，正常就说明Django+Gunicorn没问题，`Ctrl+C` 关闭。

### 配置 systemd 守护进程（开机自启、后台常驻）
新建服务文件：`sudo nano /etc/systemd/system/django.service`
```ini
[Unit]
Description=Django Gunicorn Service
After=network.target mysql.service

[Service]
User=youruser
Group=www-data
# 虚拟环境python路径
ExecStart=/home/youruser/django_project/venv/bin/gunicorn \
--workers 2 \
--bind 127.0.0.1:8000 \
myproject.wsgi:application
# 项目根目录
WorkingDirectory=/home/youruser/django_project
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

> 修改：`youruser`、项目路径、`myproject.wsgi` 替换成你自己项目名

```bash
# 重载systemd
sudo systemctl daemon-reload
# 启动
sudo systemctl start django
# 设置开机自启
sudo systemctl enable django
# 查看状态
sudo systemctl status django
```
日志查看：`journalctl -u django -f`

## 五、Nginx 反向代理配置
Nginx 作用：
1. 处理静态文件（static/media）
2. 反向代理动态请求转给 gunicorn(127.0.0.1:8000)
3. 处理SSL、域名、请求限流

新建站点配置：`sudo nano /etc/nginx/sites-available/django`
```nginx
server {
    listen 80;
    server_name 你的服务器IP 域名;

    # 静态资源
    location /static/ {
        root /home/youruser/django_project;
    }
    location /media/ {
        root /home/youruser/django_project;
    }

    # 动态请求转发给gunicorn
    location / {
        proxy_pass [http://127.0.0.1:8000](http://127.0.0.1:8000);
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

启用站点：
```bash
sudo ln -s /etc/nginx/sites-available/django /etc/nginx/sites-enabled/
# 检查nginx配置语法
sudo nginx -t
# 重启nginx
sudo systemctl restart nginx
```

## 六、防火墙放行端口
```bash
# ubuntu ufw
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp # https后续要用
sudo ufw reload
```

## 七、访问与排错顺序
1. 浏览器访问 `http://服务器IP`
2. 打不开按顺序排查：
    1. `systemctl status django` 看gunicorn是否正常运行
    2. `systemctl status nginx`
    3. Nginx日志：`sudo tail -f /var/log/nginx/error.log`
    4. Django日志：`journalctl -u django -f`
    5. 权限问题：项目文件夹权限，`www-data` 需要读取static目录

## 九、Rocky Linux 差异要点（如果你用Rocky）
- 包管理器 `dnf`，不是apt
- 防火墙是 `firewalld`，不是ufw
- Nginx、MySQL服务名一样，但SELinux容易报权限阻断，需要配置selinux规则

## 疑问：

为什么需要 Nginx 开发的时候就直接可以用啊！

一句话核心：开发时 `python manage.py runserver` 是**开发专用简易服务器**，只能用来本地调试，**不能直接暴露公网**； Nginx 不是必须直接跑 Django 代码，而是**做门面、扛流量、处理静态资源、安全防护**。
