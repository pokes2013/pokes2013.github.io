# Django项目开发完成后，Windows服务器（内网，**不用Nginx**）部署完整流程
目标：停止开发时的`runserver`，部署成Windows后台服务，内网其他电脑可以稳定访问。

## 1、开发电脑上操作（先本地做完，再上传服务器）
### ① 导出依赖清单
开发机激活虚拟环境，执行：
```powershell
pip freeze > requirements.txt
```
生成`requirements.txt`，放在项目根目录，后续一起上传服务器。

### ② 修改 settings.py 生产配置
```python
# 关闭调试模式，生产环境必关
DEBUG = False

# 允许访问地址：本机、服务器内网IP、内网网段
ALLOWED_HOSTS = ["127.0.0.1", "服务器内网IP", "192.168.1.*"]

# 静态文件配置
STATIC_URL = '/static/'
STATIC_ROOT = BASE_DIR / "static"

# 用户上传文件（图片、附件，可选）
MEDIA_URL = "/media/"
MEDIA_ROOT = BASE_DIR / "media"

# 时区
TIME_ZONE = 'Asia/Shanghai'
USE_TZ = True
```

### ③ 收集静态文件
> DEBUG=False 时，Django不再自动托管static静态资源，必须执行这条命令
```powershell
python manage.py collectstatic
```
执行完成后项目根目录生成`static`文件夹，存放css、js、图片、admin后台静态资源。

### ④ 数据库处理（二选一）
- 方案A：服务器新建空数据库，只同步表结构
```powershell
python manage.py makemigrations
python manage.py migrate
```
- 方案B：需要把开发机测试数据迁移到服务器
开发机导出MySQL备份：
```powershell
mysqldump -u用户名 -p 数据库名 > db_backup.sql
```
把`db_backup.sql`上传服务器，在服务器MySQL中导入。

> 生产环境不推荐sqlite，多用户访问优先MySQL。

### ⑤ 在开发机预测试生产模式
在项目根目录新建 `start_server.py`
```python
from waitress import serve
# myproject 替换成你的 wsgi.py 所在文件夹名称
from myproject.wsgi import application

if __name__ == '__main__':
    serve(
        application,
        host="0.0.0.0",
        port=80,
        threads=8
    )
```
开发机运行测试：
```powershell
python start_server.py
```
浏览器访问 `http://本机IP`，检查页面、静态资源、admin后台是否正常。测试完成后关闭脚本。

## 2、上传代码到Windows服务器
把项目文件夹复制到服务器，**不要上传开发机的venv虚拟环境**。
需要上传的文件：源码、requirements.txt、start_server.py

示例服务器路径：`D:\django\myproject`

## 3、服务器上配置
1. 服务器安装和开发环境同版本Python，勾选Add Python to PATH
2. 打开PowerShell，进入项目目录
```powershell
cd D:\django\myproject
# 创建虚拟环境
python -m venv venv
# 激活虚拟环境
venv\Scripts\activate
# 安装项目依赖
pip install -r requirements.txt
# 额外安装Waitress
pip install waitress
```

3. 数据库迁移（新建空库场景）
```powershell
python manage.py migrate
python manage.py createsuperuser
```
> 如果是导入备份数据，先在MySQL建好数据库，再导入sql备份文件。

4. 前台测试启动服务
```powershell
python start_server.py
```
用另一台内网电脑浏览器访问 `http://服务器内网IP`，确认全部页面正常。
测试成功后，按`Ctrl+C`停止程序，准备注册后台服务。

## 4、NSSM注册Windows系统服务（后台常驻，开机自启、崩溃自动重启）
1. 下载NSSM，解压，**管理员身份打开CMD**
```cmd
nssm install DjangoService
```
弹出窗口填写：
- Path：`D:\django\myproject\venv\Scripts\python.exe`
- Arguments：`start_server.py`
- Working directory：`D:\django\myproject`

确认保存，打开Windows【服务】，找到`DjangoService`，启动，启动类型设置为**自动(延迟启动)**。

## 5、防火墙放行端口
Windows防火墙 → 高级设置 → 入站规则，新建TCP入站规则，放行**80端口**。
内网其他电脑就可以访问 `http://服务器内网IP`。

## 6、后续版本更新流程
1. 在Windows服务里停止 `DjangoService`
2. **备份数据库**
3. 替换更新后的源码（不要覆盖media文件夹，里面是用户上传文件）
4. 激活虚拟环境，如果新增依赖：`pip install -r requirements.txt`
5. 有模型改动，执行迁移：`python manage.py migrate`
6. 静态文件修改：`python manage.py collectstatic`
7. 启动服务，测试功能

## ⚠️ 重要注意事项
1. DEBUG=False后静态文件404：确认已经执行`collectstatic`；当前方案静态文件由Waitress处理，适合内网少量用户。
2. 数据库建议定时自动备份，避免数据丢失。
3. 服务无法启动：查看NSSM里的日志，排查路径、权限、代码报错。
